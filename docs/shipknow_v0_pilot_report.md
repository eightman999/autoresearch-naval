## 1. 結論

- **0.8B の 1 モデル・マルチタスク SFT は成立した。**
  - 3 タスクとも JSON 不正 0%（T2 のスキーマ違反 0.1%）。
  - 学習なし（ゼロショット）ではほぼ何もできない（T1 正解率 0.010、T3 の有効出力 0 件）。そこから、非 LLM の強いベースラインと同水準まで上がった。
- **艦艇知識の水準は「構造化特徴の kNN / 勾配ブースティングと同程度」。** 明確に上回るのは次の 3 点。
  - T1 の細分類（0.539 vs 0.471）と確率の較正（ECE 0.023 vs 0.049）
  - T2 の装備有無・センサー
  - T3 の MAPE（0.220 vs 0.278）
- 弱いところ:
  - 戦後艦の武装（weapon F1 0.451）
  - 小型艇どうしの艦種の取り違え
  - 機関出力（MAPE 0.535）
- タスク別の valid loss は 3 つとも単調に下がり、悪化は見られない。ただし T3 単独学習との比較はしていない（ユーザー判断で省略）。干渉が無いとまでは言えない。

## 2. データ（shipknow_v0）

- NSDB の CLASS 11,144 行から、重複 145 行と主要諸元が全部欠けた 355 行を除外し、10,644 艦級を残した。
  - 艦種は 25 coarse（＋ fine 819 種）。年の取得率は 98%。
- 分割: 艦級グループ単位（union-find で同名艦級・書き分け・譲渡艦・近縁諸元をまとめた。5,118 グループ）の 80/10/10。
  - test と train の間で、艦級名・URL・諸元指紋の重複は 0 件。
- 1 艦級あたり最大 6 例（T1 / T2 / T3 を各 2）。train 49,766 / valid 6,324 / test 6,084。
- 艦名・艦級名・来歴・URL は入力に入れていない。
- パースの目視誤り率は、修正前に 20 艦 ×2 回で明確な誤り 2 件（いずれも修正済み）。書き分けは最初の 1 つだけ採用。
- 生成物: `data/navspec/shipknow_v0/`（94MB）。
- コード: `tools/shipknow_{parse,types,split,extract,build_tasks,baselines,score,infer_hf,pilot_analyze}.py`、`tools/navspec_qwen35_sft_train.py`。テスト 45 件 PASS。

## 5. 0.8B でどこまで成立したか

| 項目 | 判定 |
|---|---|
| 出力形式・マルチタスクの切り替え | 成立 |
| 艦種判定 | 実用水準の手前。勾配ブースティングに正解率で 3pt 届かない。細分類と較正は上 |
| 武装推測 | 近傍艦のコピーと同程度。戦前は 0.6 前後、戦後は弱い |
| 欠損諸元 | 寸法・速力は ±10% 以内率 6 割前後。出力と排水量は粗い。外れ値に強い（MAPE で kNN より良い） |
| 範囲・confidence | T1 は尤度で良好。T3 の数値区間は未成立 |

**解釈**: 0.8B は、データにある統計的な対応関係を、近傍法と同程度に覚えている。しかし近傍法を大きく超える「知識」までは得ていない。
次の「艦艇設計」に進む場合でも、数値の整合性は計画どおり deterministic validator と近傍艦の参照に寄せるのが妥当。

## 6. 次の候補（未実施）

1. **検索併用（近傍艦を入力に出す）**: T2 / T3 は近傍法と同水準なので、train の近傍艦の諸元・武装を入力に添えると上積みが見込める。設計フェーズの「元艦に近い設計」にもつながる。
2. **学習量・容量**: 2 epoch、または全パラメータ学習。1 epoch 終盤の valid loss は cosine で平坦化しただけで、頭打ちかは未確認。
3. **より大きいベース**（Qwen3.5 の上位サイズ）。3060 12GB に収まる範囲で。
4. **T3 単独学習との比較（干渉診断）**: 今回は省略。MoE 化を判断するには必要。
5. **T3 の区間**: サンプル数を 20 程度に増やす、または分位点を直接出力させる学習。
6. **艦種ラベル**: 小型艇（patrol / amphibious / fast_attack_craft / coast_guard）の境界の見直し。
