# shipknow v1 レポート: 近傍艦を入力に添えた 3 タスク学習

作成: 2026-10-06 / 前段: [shipknow_v0_pilot_report.md](shipknow_v0_pilot_report.md)
生データ: [shipknow_v1/](shipknow_v1/)（採点 `v1_test_score.json`、近傍ベースライン `baselines_rag_test.json`、学習ログ・予測 `rag_k3_run/`、コピー・訂正分析 `copy_correct_analysis.txt`）

## 1. 結論

- **近傍艦 3 隻を入力に添えると、3 タスクとも v0 より良くなった。** 主な指標はすべて、非 LLM のベースライン（同じ近傍を答えにそのまま使う方式を含む）を上回った。
  - T1・T2 の差は小さい（1〜4pt）。
  - T3 の差ははっきりしている。±10% 以内率は、最良のベースライン 0.488 に対して 0.550。
- **単なるコピーではない。**
  - T1: 近傍の多数決と 89% 一致するが、近傍が外れた例の 22% を正しく直している。逆に、近傍が正しいのに外すのは 4%。
  - T3: 近傍の中央値が ±10% を外した項目のうち、30% を ±10% 内に直している。
- 学習はユーザー判断で step 2,400 で停止した。評価は best（step 2,200 / 3,110）。v0 は 3,110 step まで学習しているので、v1 の方が学習量は少ない。

## 2. 方法

- データ `data/navspec/shipknow_v1_rag/`: v0 と同じ例（id・分割・正解が同一）の user JSON に、`neighbors`（k=3）を追加した。
  - T1 の近傍: 諸元・武装・センサー・艦種
  - T2 の近傍: 艦種・年・国・船体数値・武装・センサー
  - T3 の近傍: 全数値諸元と主要武装
  - 艦名・艦級名・URL は出していない。
- retriever（`tools/shipknow_retriever.py`）: train の数値（対数）を標準化した重み付き距離に、国一致・艦種一致（T2/T3 のみ）・武装種別の Jaccard（T1/T3）を加えた。
  - その例の入力に見えている項目だけで検索する。隠した数値、隠した武装、T1 の艦種は使わない。
- リーク検査（`leakage_check.json`）は、全分割で次がすべて 0 件。
  - 近傍が train 外の艦
  - 近傍が自分自身
  - train 例で、近傍が同じ艦級グループ（leave-group-out）
  - v0 と正解が食い違う例
- 学習: v0 と同設定（Qwen3.5-0.8B、LoRA r64、全層、lr 2e-4 cosine、実効バッチ 16）。
  - 入力が長いので bs2×GA8。train は 3,913 万トークン（v0 の 2.6 倍）、2,860 tok/s、ピーク 10.8GiB。
  - step 2,400（約 2.9 時間）で停止。

valid loss:

| step | 全体 | T1 | T2 | T3 |
|---|---:|---:|---:|---:|
| 0（v1） | 0.753 | 0.651 | 0.561 | 1.483 |
| 0（v0） | 1.181 | 1.135 | 1.014 | 1.767 |
| 2,200（v1, best） | **0.217** | **0.125** | **0.200** | **0.386** |
| 3,110（v0, 最終） | 0.223 | 0.126 | 0.204 | 0.404 |

## 4. コピーか、判断か

| | 近傍との一致 | 近傍が外れたとき v1 が正す率 | 近傍が正しいとき v1 が外す率 |
|---|---:|---:|---:|
| T1（対 近傍 3 隻の多数決） | 0.892 | 0.215（455 件中 98） | 0.039（1,601 件中 63） |
| T1（対 近傍 1 隻） | 0.873 | 0.260（466 件中 121） | 0.047 |
| T2（対 近傍 1 隻、武装リスト完全一致） | 0.407 | 0.055（1,665 件中 92 が完全一致） | — |
| T3（対 近傍 3 隻の中央値、±10% 基準） | 0.293（値が完全一致） | 0.295（1,720 項目中 508） | 0.184（1,640 項目中 301） |

- T1 は近傍に強く依存しつつ、正味でプラスになっている（直す 98 件 > 壊す 63 件）。
- T3 は近傍を足がかりに補正しており、正味のプラスが最も大きい（直す 508 > 壊す 301）。
- T2 はリスト全体の正解まで直せることは少ない。ただし F1 と門数の改善を見ると、部分的な修正は効いている。

## 5. 所見と次の候補

- 0.8B は「近傍艦を参照して補正する」使い方なら、非 LLM の手法を明確に超えられる。設計フェーズの「要求 → 類似艦を検索 → 設計 JSON → validator」構成と相性が良い。
- 学習を最後まで回していない（2,200 / 3,110 step）。完走させれば、もう少し伸びる余地がある。
- 次の候補（未実施）:
  1. 完走、または 2 epoch。
  2. k を 5 に増やす、または近傍の表示を圧縮する（トークン長とのトレードオフ）。
  3. T3 の区間: サンプル数を増やす、または近傍のばらつきを区間に使う。
  4. 艦艇設計フェーズの試作。要求から近傍艦を検索し、設計 JSON を生成し、既存 validator で検査する。
